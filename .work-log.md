#### Incidente: `Cannot GET /api/v1/clients?page=1&pageSize=20`

- Síntoma: al abrir la página de clientes no aparecía el buscador; la API respondía `Cannot GET /api/v1/clients?page=1&pageSize=20` aunque `ClientsController` ya estaba implementado y registrado.
- Causa: el contenedor `api` monta el volumen nombrado `vet-manage_api_generated` en `/app/src/generated`, que conservaba un Prisma Client generado antes de los modelos `Client`/`Pet`/`Batch`. La compilación en modo watch falló con 11 errores TS (`ClientWhereInput`, `prisma.client`, `PetSex`, ...) y el proceso siguió sirviendo un `dist` antiguo sin las rutas nuevas. Además, `tsconfig.build.tsbuildinfo` incremental junto con `deleteOutDir: true` dejó `dist` solo con `.d.ts` y sin `dist/main.js` (`Cannot find module '/app/dist/main'`).
- Corrección aplicada: `docker compose exec -T api npx prisma generate`, `docker compose exec -T api sh -c 'rm -rf /app/dist /app/tsconfig.build.tsbuildinfo'` y `docker compose restart api`. No requirió cambios de código: el registro de rutas era correcto.
- Verificación en runtime: logs muestran `Mapped {/api/v1/clients, GET}` y `Mapped {/api/v1/clients/:clientId/pets, GET}`; `GET /api/v1/health` → 200; `/api/v1/clients?page=1&pageSize=20` sin sesión → 401 y con token de `recepcion@vetmanage.local` → 200 con datos demo.
